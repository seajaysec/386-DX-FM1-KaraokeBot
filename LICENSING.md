## JieLi SDK files in the packages (Apache-2.0)

JieLi Technology makes the FM-1's AC791N processor. A `.fwsc` package made by
`tools/build.py` (with `tools/fm1pkg_make.py`) holds unmodified files from the JieLi AC79 SDK,
`AC79NN_SDK_V1.2.1_2023-12-13` (<https://gitee.com/Jieli-Tech/fw-AC79_AIoT_SDK>,
`cpu/wl82/tools/`). They are read from your SDK checkout at build time (see `BUILDING.md`).
No SDK files are in this tree.

| File in the package | What it is |
| --- | --- |
| `uboot.boot` | the first-stage boot loader (SPL) |
| `cfg_tool.bin` | the chip configuration block |
| `eq_cfg_hw.bin` | the default hardware EQ table |

These files are licensed under the Apache License, Version 2.0 (`LICENSES/Apache-2.0.txt`),
not under the GPL. Their copyright stays with JieLi Technology. The SDK has no NOTICE file.
They are separate programs and data placed alongside the GPL app in the package. 386DX itself
stays GPL-3.0-only.

## Studied, not used

MonkSynth by Jonathan Taylor (<https://github.com/JonET/monksynth>, MIT) was read while the
singing was designed. It showed that a voice can set its pitch and its vowel formants
separately. No MonkSynth code, tables or constants are in 386DX, and nothing from it is linked
or copied.

## Songs

Greensleeves, the song the firmware saves in S1 the first time it starts
(`firmware/assets/demo_songs.json`, made into a 386DX song by `tools/demo_song.mjs`): the melody and
words are traditional; the lyric underlay follows the arrangement by Mjchael and JuLiBu on
Wikibooks (<https://pl.wikibooks.org/wiki/%C5%9Apiewnik/Greensleeves>), CC BY-SA, with further
verses underlaid for 386DX. The adapted score is shared under the same licence.

Factory songs (`firmware/assets/preset_songs.json`) and the web companion's songs
(`web/songs/`) are content, not code. Every song in a release must carry its own `source`
and `license` fields. Only public-domain, CC0 or otherwise redistributable material is
accepted. A release build (`./build.sh --release X.Y`) refuses songs without them, and
refuses local-only demo content (`DX_LOCAL_DEMOS=1`).

## Release contents

`./build.sh --release X.Y` writes `build/release-X.Y/` with:

- the package and the app image
- `SHA256SUMS`
- `SOURCE.txt` (the source repository and the pinned tools)
- `LICENSE`, `LICENSING.md`, `BUILDING.md`
- `LICENSES/`

Distribute that folder as a whole. Publish the matching source in the public
repository.

## No vendor material

The firmware links no M-VAVE code and contains no M-VAVE data. The packages hold only 386DX and
the three SDK files above.
